# git-your-ship-together (GYST)

GYST is one repository of reusable GitHub Actions workflows. Instead of every
project keeping its own six copies of a lint job, a test matrix, a container
release, a security scan and a dependency bot, each project keeps three short
files that say what is specific to it, and calls the shared workflows for the
rest. A bug fixed in a shared workflow is fixed in every project on its next
pin bump. The projects that call it today are the Python daemons, the
Hammunition suite, a firmware project and a few lab repositories;
[`baseline/repos.txt`](../../baseline/repos.txt) is the list, 23 repositories
as of 2026-10-05.

It is also written to be read. Every rule in it came from something that
broke or something that was measured, and the wiki says which. If you have
never written a GitHub Actions workflow, start with
[Getting started](Getting-started.md) and look words up in the
[Glossary](Glossary.md). If you have, go to the workflow page you need: each
one lists the exact inputs (generated from the YAML, so they cannot be wrong),
the jobs, and which job is allowed to hold a token.

**Who it is for.** The maintainer's own projects first. Second, anyone who
wants to see what a hardened CI setup looks like end to end, with the
reasoning and the mistakes left in. Third, anyone who wants to copy it: see
[Adopting GYST in your own project](Adopting-GYST-in-your-own-project.md).

**The one-sentence rule.** CI in every repository calls these workflows, and
only what is genuinely unique to a project stays local.

**What every page answers, in this order:** what this is, why it exists (the
measured incident or the threat behind it), how to use it, and what it
refuses to do.

## Where the authority is

The repository's [README](../../README.md) is the single source of truth and
stays that way; this wiki explains it and does not replace it.
[BASELINE.md](../../BASELINE.md) is the list of settings every calling
repository must meet, and [docs/DESIGN.md](../DESIGN.md) holds the threat
model. Where the wiki and the repository disagree, the repository is right and
the wiki has a bug: open an issue.

## One-time owner step for this wiki

This wiki is generated by `.github/workflows/wiki.yml` from `docs/wiki/` and
is never written by hand. GitHub does not create a wiki's git repository until
someone saves its first page in the web UI. Until the owner opens the Wiki tab,
chooses "Create the first page" and saves anything, the publish job fails with
a message naming that step, and nothing else in CI is affected. After that one
save, every push to `main` replaces the whole wiki.
